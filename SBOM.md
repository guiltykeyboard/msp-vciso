# Software bill of materials

The authoritative machine-readable inventory is [the CycloneDX JSON SBOM](sbom/watchtower.cdx.json). It is committed so self-hosters and reviewers do not need access to a particular CI run to inspect it.

The `Repository metadata` workflow regenerates the SBOM with Anchore Syft, normalizes volatile timestamps and identifiers, and fails when the committed SBOM or repository badges differ. Generated metadata is reviewed and committed with the source change instead of being pushed to `main` by an unchecked bot commit. Tagged release source archives receive SLSA provenance through the OpenSSF SLSA generic generator.

The repository currently has no third-party application runtime dependencies. `requirements-dev.txt` records development-only Python tooling such as Pylint. As application packages and container images are introduced, their package inventories must appear in this SBOM or in a release-specific SBOM linked from here.

Repository language percentages and line counts are generated by `tools/update_badges.py`. “Lines of code” means nonblank physical lines in recognized source-code files returned by Git; documentation, framework JSON, generated API documentation, badges, SBOM output, vendored code, and build output are excluded. The script also changes the README image query whenever badge content changes so GitHub and browser caches cannot indefinitely display an old value.
